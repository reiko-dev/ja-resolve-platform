T01 CORRECTION — NEGATIVE CONTROL (reset authorization / P1 of the external review)
==================================================================================
Finding (external review, PR #32, P1): `scripts/tow/db-reset.js` exported
`resetDatabase(db)`, which ran `DROP SCHEMA IF EXISTS public CASCADE` on an
arbitrary Knex object with no authorization bound to that connection. The gate
and the e2e suite called that raw function.

Correction under test: the destructive primitive is private (not exported); the
only public entry point is `resetDatabase({ purpose, env?, confirm?, dryRun? })`,
which resolves the target, authorizes it, and only then creates the connection
FROM THE AUTHORIZED TARGET.

Method: for each bypass, a minimal mutation is applied to the source, the
targeted suite is executed, the file is restored byte-identically (sha256
compared before/after) and the suite is re-run GREEN. A mutation that does not
turn the suite RED means the suite does not actually prove the rule.

Targeted suite: tests/tow/baseline/dbBaselineSafety.test.js (48 cases; the
RESET-DIRECT-1..8 block is the one that proves this finding).
Script: /tmp/nc-reset-authorization.sh (raw logs: /tmp/nc-nc1-red.log,
/tmp/nc-nc2-red.log, /tmp/nc-nc3-red.log, /tmp/nc-nc-green.log).
Re-run note: this control was executed twice — once on the first version of the
correction and again after the live e2e suite caught a real bug in the misuse
check (a real Knex instance is CALLABLE, so the generic "received function"
branch fired before the connection branch). The hashes and counts below are from
the final run; an offline regression test for the callable shape was added
(`RESET-DIRECT-7 › a CALLABLE Knex double (the real shape) gets the connection
diagnosis`).
